**What changed and why (2–5 sentences):**
Three 2026-09-05 findings shared one shape — the tool reported healthy while doing nothing (fastify refreshed cleanly and answered nothing; 18 configured libraries sat `not cached` for days). `vibectx doctor` makes coverage a measured property: for every configured library it reports source kind (`full-text` / `index-only` / `readme` / `unreachable`, classified by structure, never byte count), cache age and staleness, and the result of one or more probe queries run through the *same* code path `get_docs` uses (`answered` / `index-followed` / `no match`), with followed/dropped link counts exposed structurally. It ships as a CLI subcommand (`vibectx doctor [--json] [--library] [--config] [--offline]`, exit 0/1/2), an MCP tool `doctor()`, a `[kind]` marker in `list_libraries`, an optional `probeQueries` field on registry/config entries (one default per built-in library), and a weekly GitHub Actions job that fails on any unhealthy library and uploads the JSON report. The `--json` report carries `schemaVersion: 1`.

**Blast radius if wrong (prod deploys on merge — be honest):**
Product: `get_docs` text is byte-identical (`getDocs` wraps `getDocsDetailed`; asserted by test); the MCP server startup path is unchanged unless a bare `doctor` token is present in argv. A wrong doctor verdict misleads a human or CI, not an agent's answers. `src/fetcher.ts` `offline` option is additive and dead when the flag is absent (verified by whitespace-insensitive diff and by the security gate). CI: the new workflow runs weekly with `contents: read` only; a false ✗ costs a red badge, not a deploy.

**Behaviour changes worth knowing (release notes):**
1. New CLI subcommand `vibectx doctor`; new MCP tool `doctor`; `list_libraries` rows gain a trailing `[kind]`.
2. `LibraryEntry.probeQueries?: string[]` in config (validated: array of non-empty strings; `[]` behaves as absent → derived query, documented).
3. Default fastify probe is "lifecycle hooks" (MEASURED: the raw-GitHub fallback `Index.md` has zero "querystring" occurrences, so a probe must answer on whichever candidate URL is served).
4. Doctor runs at most 3 libraries concurrently; one library's internal error (e.g. corrupt cache metadata) is reported as an `unreachable` row with the error, never a crashed run.
5. `ttlHours: 0` entries are exempt from the 2× TTL staleness rule.
6. Weekly `doctor` workflow (Mondays 06:00 UTC + manual). Expected first result, NOT VERIFIED from the sandbox: aws-cdk may ✗ if its docs-site `llms.txt` is absent, because the README fallback does not mention Kinesis/Firehose — the intended signal.
