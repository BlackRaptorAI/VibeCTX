**What changed and why (2–5 sentences):**
Retrieval was the product's weakest surface: `rankSections` was keyword overlap, the tokenizer had no stemming and no camelCase split (so `useEffect` never matched "use effect"), `splitSections` flattened heading levels so an H4 lost its H2/H3 parents, and there was no code-first mode. This change replaces the ranker with Okapi BM25 over the per-call section corpus (heading tokens weighted, deterministic document-order tie-break, still zero dependencies and offline), gives every section a heading path that the output prints, adds `get_docs(..., mode: "snippets")` which ranks fenced code blocks and returns them with one line of context under the same token budget, and rebuilds the tokenizer with a linear camelCase scanner and a light stemmer. It also adds a measured evaluation — a versioned gold set of the 60 registry probe questions and a script that runs the *old* ranker and the new one side by side — so the claim "retrieval got better" is a number, not an assertion.

**The headline finding is that the number does not support the claim yet.** On the corpus this sandbox can reach, BM25 scores 18/60 top-1 hits and the legacy ranker scores 18/60. See §5 row 1: the done-when is **not met**, and the reason is the corpus, not a regression.

**Blast radius if wrong (prod deploys on merge — be honest):**
Every `get_docs` answer changes shape (heading paths) and can change order (BM25). A ranking regression would degrade every answer the product gives; the eval shows +0/−0 hits against the old ranker on 60 questions, so the risk is bounded by measurement rather than by inspection alone. The snippet renderer is a new path that puts attacker-influenced text into the model's context inside a markdown fence: a fence-width defect would let a crafted code block break out of (or swallow past) its own fence, and a budget defect would let a crafted document blow through `maxTokens` — both were found by the security gate (a 2000× budget overshoot; two fence-escape shapes) and both are now closed and pinned by tests using an independent CommonMark fence matcher. The tokenizer is also used by `rankLinks`, so index-link *selection* changed; the SSRF guard runs downstream of ranking (`isAllowedLink` on every candidate, re-checked in `fetchLinkedPage`), so selection can never widen what is fetchable.

**Behaviour changes worth knowing (release notes):**
1. **BM25 ranking (D-24).** Okapi BM25 (k1 1.2, b 0.75; IDF `ln(1+(N−n+0.5)/(n+0.5))`) over the sections of the current call's corpus; a section's own heading tokens count 3×, its ancestor-path headings 1×, body 1×; zero-scoring sections dropped; ties broken by document order via an explicit index. 5.8 MB corpus ranks in 119 ms (MEASURED; D-24's bound was 1.5 s).
2. **Tokenizer (D-23).** Lowercase, split on non-alphanumerics and camelCase/PascalCase via a linear scanner, keep the whole lowercased compound as well, light stemmer with Porter step-1b-style repairs (de-doubling; silent-`e` restore on a three-letter CVC stem), small stopword list with an all-stopword fallback, 2-char tokens kept, `MAX_TOKEN_CHARS` 64. Documented non-convergences: `using`, `handler`, `middleware`, `indices`, `setting`/`set`, `seed`, `embed`/`embedded`.
3. **Heading paths (D-25).** Every section carries `level` and `path`; output renders `## Auth > Row Level Security > Policies`. A `#` line inside a fenced block is no longer a heading (with two pinned limitations: an unclosed fence runs to end of document, and a fence indented 4+ spaces or by a tab is not recognised — MEASURED as 0 of 802 fence lines across the 30 fetchable documents).
4. **`mode: "snippets"` (D-26).** New optional `get_docs` parameter (zod enum, default `"sections"`). Ranks fenced code blocks by their section's BM25 score plus 2× query overlap with the code itself, returns each with its heading path, its language, and the nearest preceding prose line, under the same `maxTokens` budget. Distinct no-match message; `matched` counts snippets. Index following, stale prefix and the resolution provenance line are identical to sections mode.
5. **Rendering is inescapable and bounded (D-28/D-29/D-30).** A snippet's fence is one backtick wider than the longest run in its code *and* its rendered language, so no code content and no info string can break or swallow past the fence; the assembled chunk is clipped to the budget, so an attacker-controlled heading path, context line or language cannot exceed `maxTokens`; those three derived fields are `cleanText`-stripped and clipped (200/200/20). Section **bodies** are deliberately not cleaned — the body is the document, and cleaning it would corrupt the answer; that asymmetry is pinned by a test.
6. **Per-document splitting (D-31).** The primary document and each followed index page are split into sections separately and the lists concatenated, so an unclosed fence in one document can no longer swallow another. `matched` and `returnedFromFollowed` semantics unchanged.
7. **Measured evaluation (D-27/D-32).** `docs/eval/probe-gold.json` (`schemaVersion: 1`, 60 questions, 37 marked `unanswerable` on this corpus) and `scripts/eval-retrieval.mjs`, which validates the gold set's shape before it measures anything and refuses to print numbers otherwise. Results in `docs/eval/2026-09-06-par-658.md`. Dev-only; not shipped (`package.json` `files: ["dist"]`).
