**What changed and why (2–5 sentences):**
Config was only reachable through `--config <path>`, and MCP clients launch the server with a fixed command line, so the "commit it and every teammate's agent gets the same context" story did not work. The server and every CLI subcommand now resolve config in one order — `--config` flag, `VIBECTX_CONFIG`, `./vibectx.config.json` found by walking up from the working directory to the repository root, `$XDG_CONFIG_HOME/vibectx/config.json` (default `~/.config/vibectx/config.json`), shipped defaults — with the project file layering over the user file over the defaults by library name, through the one merge path that already applied D-06/D-07. The file is validated with zod and every failure is one cleaned, bounded line naming the file, the entry and the field. `list_libraries` opens with the config sources actually loaded. A broken *discovered* file is skipped loudly (stderr once, `NOT LOADED` in the header, `doctor` unhealthy, a `warm` note) while a broken explicit source still exits 2, and the walk-up never trusts a directory owned by another user.

**Blast radius if wrong (prod deploys on merge — be honest):**
Anyone who can commit to a repository you `cd` into can now put a library — including an override of a shipped default such as `react` — into every teammate's agent context, pointed at an https host of their choosing. The security gate judged this acceptable for a committed team config (cloning and running a repo's toolchain already grants more), provided it stays visible: `list_libraries` names the file, `get_docs` stamps `Source: <url>` on answers, and the link policy (`allowedHosts` normalisation, https-only, no IP/localhost/`.local`) is unchanged and still bounds what a hostile entry can make the server fetch. A discovery defect would read config from an unintended directory: the walk stops at `.git`, at a foreign-owned directory, or at cwd when no `.git` exists; symlinked files are allowed but capped at 1 MiB and parsed only as JSON. A validation defect would take the server down: discovered failures degrade instead. Existing `--config` users see no change except that an `http:` URL — which the fetcher never fetched — is now a config error.

**Behaviour changes worth knowing (release notes):**
1. **Zero-flag team config.** `vibectx.config.json` in the repository (any directory between cwd and the `.git` root; nearest wins) is loaded automatically by the server and by `doctor`, `resolve`, `warm`. A user-level `~/.config/vibectx/config.json` (or `$XDG_CONFIG_HOME/vibectx/config.json`) layers beneath it. **D-14:** flag > env > project > user > defaults; an explicit `--config` or `VIBECTX_CONFIG` is authoritative and skips discovery (0.1.x behaviour preserved).
2. **D-15:** the walk-up stops after the directory containing `.git` (file or directory); with no `.git` only cwd is checked; multiple project files are not layered (monorepo layering is a follow-up). **D-20:** a directory owned by a different uid stops the walk (git `safe.directory` analogue; skipped where `getuid` is unavailable); a foreign directory holding a config is named in the header and on stderr.
3. **D-16:** legacy `docs-cache.config.json` is accepted at the same locations through 0.2.x with a deprecation note; if both names exist, `vibectx.config.json` wins.
4. **D-17 / D-22:** zod validation; every error is one line ≤ 300 chars, control characters stripped: `<display path>: libraries[i].<field> ("<name>"): <message>`; JSON syntax errors report line and column when the parser supplies a position, otherwise `invalid JSON` — never file content; files over 1 MiB (ASSUMED cap) refused. Display paths are `./…` beneath cwd, `~/…` under HOME, absolute otherwise, cleaned and clipped at 200 chars at construction.
5. **D-19:** a discovered file that fails to load is skipped — the other layers load, one stderr line, `config: ./vibectx.config.json (project) — NOT LOADED: <reason>` in `list_libraries`, `doctor` reports `✗ config …` with a `configIssues` array (additive key, no schema bump) and exits 1, `warm` adds `config: <display> (<scope>) not loaded: <reason>` to `notes[]`. Explicit flag/env failures remain fatal (exit 2).
6. **D-21 (compatibility):** `libraries` is optional (`{}` loads as defaults; `null` → empty); `ttlHours: 0` accepted; unknown top-level and entry keys ignored (a 0.3 config loads on 0.2). **The one breaking change:** `urls` must be `https:` — documented under "Upgrading from 0.1.x".
7. **D-18:** `list_libraries` starts with `config: <sources, highest precedence first, with scope>` or `config: none (shipped defaults)`; config-supplied `name`/`aliases`/`description` are cleaned and clipped at 200 chars when rendered.
8. `Registry` gains an optional `config` field (`files`, `notes`); `loadRegistry(configPath?)` keeps its signature as a wrapper over `loadRegistryFrom(resolution)`.
