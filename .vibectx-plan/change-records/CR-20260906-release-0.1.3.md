**What changed and why (2–5 sentences):**
Field report PAR-704: fastify's `llms.txt` (106,561 chars, a pure link index) returned `No sections matched` for every topic while `list_libraries` showed it healthy. Root cause: `looksLikeIndex()` refused any document ≥ 100,000 chars, so no index links were followed. This release removes the size cap (density over the first 200 non-empty lines), resolves relative index links against the source URL, scales the follow budget 3→5 for large indexes with a ~2 MB accumulation stop, and makes every dropped link visible in the response. While widening link-following, the gates found and this release closes three pre-existing weaknesses: a quadratic link regex (ReDoS from a hostile doc), an SSRF redirect escape (a same-origin link could 302 to any host and be served/cached), and unbounded response bodies (now 25 MiB primary / 2 MiB followed page). Version 0.1.2 → 0.1.3.

**Blast radius if wrong (prod deploys on merge — be honest):**
Every consumer that runs `npx -y @blackraptorai/vibectx` at the new pin — including every Paragon coding session via `.mcp.json` once repinned. A wrong index classification degrades answers (more or fewer links followed); a wrong guard change could either block legitimate same-origin pages (visible: "Skipped N") or, in the worst case, re-open the redirect escape — covered by tests `test/fetcher.test.ts` (redirect refusal ×2, downgrade, same-origin path, primary exemption). No data leaves the machine; no telemetry.

**Behaviour changes worth knowing (release notes):**
1. Index classification is size-independent and counts relative links; a long guide whose first 200 non-empty lines are >40 % relative-link TOC now gets bounded link-following. Anchor-only TOCs do not.
2. Followed links are re-checked after redirects: the final URL must be `https:` on the source origin, else the body is never read or cached and the link is reported as skipped. Primary registry URLs are deliberately exempt (they legitimately redirect across hosts).
3. Response byte caps: 25 MiB per primary document, 2 MiB per followed page, enforced via `Content-Length` and while streaming.
4. `getLinkedPage` no longer serves stale cache when a fresh fetch is refused or too large.
5. Hrefs containing `(`, `[` or `]` are skipped whole (previously truncated to a wrong URL).
6. Residual (release-note): a linked page cached *before* this fix from an escaped redirect is served until its 7-day TTL expires; `refresh` re-fetches primaries only. Users can clear `~/.docs-cache-mcp/<lib>/` to force it.
