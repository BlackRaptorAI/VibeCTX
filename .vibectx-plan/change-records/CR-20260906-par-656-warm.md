**What changed and why (2–5 sentences):**
Zero-config is the 0.2.0 promise: a vibe coder should install VibeCTX and have the docs for *their* stack cached without writing a config. `vibectx warm [dir]` / MCP `warm_project(dir?)` reads the project's manifests (`package.json`, `pyproject.toml`, `requirements*.txt` with one level of `-r`; lockfiles only when no manifest exists), maps each dependency to a curated entry or resolves it through the PAR-655 chain under the existing 100/h cap, fetches each primary document (no link following), and prints a table plus `N/M dependencies cached` (exit 0/1/2, `--offline`, `--json`, `--force`). A project record `<cacheRoot>/projects/<sha256(dir)>.json` (schemaVersion 1, atomic, validated on read) feeds a one-line summary in `list_libraries` and a 24 h memo that stops failing names re-spending the resolution budget. On server start, configured (non-resolved) libraries that are uncached or stale are revalidated in the background (etag-first, concurrency 2, never blocking a tool call, `warming…` visible, `VIBECTX_NO_AUTOWARM=1` opt-out, aborted when the transport closes). All on-disk writes (cache, resolved store, project record) now go through one atomic temp+rename helper with a startup sweep of orphaned temp files.

**Blast radius if wrong (prod deploys on merge — be honest):**
`warm` reads files from a directory the user (CLI) or the model (MCP, confined to the server's real cwd or beneath) names, and turns their contents into outbound fetches — up to 4 concurrent, each bounded by the PAR-655 per-name and per-hour caps. A parsing defect would be a denial-of-service on the user's own machine (the round-one cubic regexes were exactly that: 11.3 s / 31.8 s on a 1 MiB hostile manifest, now 0.5 ms / 0.2 ms — MEASURED); a containment defect would let a hostile repo make the model read manifests outside the project (found twice by the gates, closed twice, now decided on real paths with the nearest-existing-ancestor rule). The temp-file sweep is the first delete path in the product: it is confined to the cache root and its known children, matches only `<name>.<pid>.<ms>.tmp`, never follows symlinks, and skips files younger than 60 s. A wrong autowarm would hang the server or spend the budget on start; it is cancellable, bounded to configured entries, and off for subcommands.

**Behaviour changes worth knowing (release notes):**
1. New CLI `vibectx warm [dir] [--offline] [--json] [--force] [--config <path>]` and MCP tool `warm_project(dir?)` (D-12: `force` is CLI-only). Eight row statuses (the schemaVersion 1 vocabulary): `cached`, `already fresh`, `resolved+cached`, `unresolved`, `unresolved (recent)`, `unreachable`, `skipped (rate cap)`, `denied (noise list)`. A stale entry that cannot be revalidated is kept and reported `unreachable`.
2. Dependency discovery: package.json deps + devDeps (`npm:` aliases unwrapped; `file:`/`link:`/`workspace:` skipped), pyproject `[project]` / optional / dependency-groups / poetry tables (path/git/url deps skipped), `requirements*.txt` with one level of `-r`; lockfile fallback (package-lock v2/v3, pnpm) only when no manifest is present; yarn/uv/poetry lockfiles reported, not read. PEP 503 normalisation and cross-manifest dedup. Exported `DEPENDENCY_DENYLIST` (typescript/pytest/ruff kept). Symlinks are refused everywhere in discovery (D-09). Manifests over 32 MiB are not read (ASSUMED cap).
3. **D-10 (amended):** `warm_project(dir?)` accepts only the server's working directory or a directory beneath it, decided on real paths (a symlinked subdirectory pointing outside, a sibling-prefix directory, `..`, an absolute path, and a non-existent tail under a symlink are all refused). The CLI is unrestricted.
4. **D-11:** curated entries match by name regardless of ecosystem; when the manifest ecosystem differs the row carries a note. An `ecosystem` field on entries is a follow-up.
5. Project record: `<cacheRoot>/projects/<sha256>.json`, schemaVersion 1, row key order `name, ecosystem, source, library?, status, url?, note?, failedAt?`; validated field-by-field on read (bad `source`/`status`/`ecosystem`/`failedAt` drop the row, bad `url` drops the field, notes truncated to 512, bad `warmedAt` rejects the record); the timestamp shape and the status vocabulary are part of schemaVersion 1. Lower on-disk versions are replaced, higher are protected (K2, same rule as `resolved.json`, one shared helper). **D-13:** record persistence is best-effort — a write failure is a warn line and a report note, never a failed run. The record stores the absolute project directory and `list_libraries` shows it to the model; a moved project gets a new record and the old one is orphaned (pruning is a follow-up).
6. `list_libraries` gains a one-line project summary and `warming…` markers; `unreachable` and `skipped (rate cap)` are counted under `unresolved` in that line (split queued).
7. Autowarm: only in long-lived server mode, after transport connect, configured non-resolved entries that are uncached/stale, concurrency 2, errors swallowed and reported; aborted on transport close. `src/index.ts` now closes the server on stdin end and exits after a 100 ms grace (MEASURED ~100 ms; previously the process could linger).
8. Storage: `writeCache`/`touchCache`, `resolved.json` and project records are written temp+rename via `src/atomic-store.ts`; orphan temp files older than 60 s are swept at server start and at the start of each warm run. Pre-existing 0.1.x cache meta files read unchanged (MEASURED); an unparsable `fetchedAt` now reads as stale rather than fresh forever.
9. Registry aliases added: `react-dom→react`, `@supabase/supabase-js`, `@trpc/server`, `@trpc/client`, `@clerk/nextjs`, `@anthropic-ai/sdk`, `@playwright/test`, `@sveltejs/kit`, `@tanstack/react-query`, `@tailwindcss/postcss→tailwindcss`.
10. Internal: `src/server.ts` extracts `buildServer`/`startServer` (tests drive the real server over `InMemoryTransport`); `src/doctor.ts` exports `mapLimit`; `ResolveOutcome.limited`.
