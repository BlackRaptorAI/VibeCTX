**What changed and why (2–5 sentences):**
The audit's finding was that process was consuming more founder time than product: thirteen files under `docs/` against five source files, every commit for six weeks being governance housekeeping, and an empty retro log. This change writes the repo's change-record rule down once (`docs/change-record-policy.md`), makes CI enforce exactly that rule and nothing more, and puts four real rows in the retro log — then finishes the rebrand the code still carried (`~/.docs-cache-mcp` → `~/.vibectx`, `DOCS_CACHE_DIR` → `VIBECTX_CACHE_DIR`, a hard-coded version string → the package manifest) and closes the three hardening items the audit listed: a cache size cap with LRU eviction, structured diagnostics that tell a 404 from a timeout from a DNS failure, and a metrics script. Atomic writes and the end-to-end MCP test were already shipped by PAR-656 and PAR-707 and were not redone.

**Blast radius if wrong (prod deploys on merge — be honest):**
Two of these are genuinely dangerous and both bit. Eviction deletes files a user cares about: the security gate's first probe found that against a **symlinked cache root** it followed the link and **deleted `Documents/project/thesis.md`** — a real file outside the cache. The migration renamed a symlinked `~/.docs-cache-mcp` *as a symlink*, so `~/.vibectx` became a link aimed wherever the attacker chose. Both are closed under D-46 (lstat first, refuse anything that is not a real directory, say so once) and pinned by tests using real filesystem symlinks and real planted files. The cap then turned out not to hold within a run — twelve 1 MiB writes against a 2 MB cap left 12.5 MB on disk with zero evictions and no warning — which is not a cap; that is fixed too. Beyond the cache, a CI-gating mistake would weaken the mechanism that requires this very document: the gated list only grew, and the matcher now also reads `previous_filename` so a rename cannot slip a gated file past it.

**Behaviour changes worth knowing (release notes):**
1. **Cache location (D-45).** `~/.vibectx` replaces `~/.docs-cache-mcp`, migrated once by rename on first run — never copied, never onto an existing target, never following a symlink; a failed rename falls back to the old path for that run and says so once. `VIBECTX_CACHE_DIR` replaces `DOCS_CACHE_DIR`, which keeps working through 0.2.x with a once-per-process deprecation note. A 0.1.x binary run after the migration starts with a cold cache; the README documents that and the `DOCS_CACHE_DIR=~/.vibectx` escape hatch.
2. **Cache size cap.** `VIBECTX_CACHE_MAX_MB` (default 512 — ASSUMED) with least-recently-fetched eviction, swept amortised (at the first write, then every `min(16 MiB, cap/2)` written). Evictions are reported on stderr and in `doctor`'s table. An unparsable or negative value falls back to the default and now says so once, naming the value it refused.
3. **Structured diagnostics.** `VIBECTX_DEBUG=1` emits `vibectx [debug] <event> key=value` lines that distinguish a 404 from a timeout from a DNS failure from a refused redirect target from a body-cap stop — the audit's complaint was that `fetchUrl` collapsed all of them into `miss`. Every field is control-character-stripped and clipped; the README enumerates the exact reason vocabulary and states that the lines are human/grep output, not a versioned contract (`--json` and the MCP payloads are the versioned surfaces).
4. **Version from the manifest.** The MCP server version and the user-agent both read `package.json` rather than a hard-coded `"0.1.3"`, with a guarded fallback to `0.0.0-unknown` if the manifest cannot be read, and a test that fails if anyone re-hardcodes one.
5. **Governance.** `docs/change-record-policy.md` states the rule: one CR per tagged release for supply-chain and publish concerns, plus one per PR touching a gated surface. **D-44:** the gated list is `.github/`, `.claude/`, `package.json`, `src/fetcher.ts`, `src/link-policy.ts`. Cache, atomic-store and search-index paths stay convention-routed — hard-gating them would put a CR on every retrieval change, which is the over-governance this issue exists to remove, and the policy names that cost rather than hiding it. `docs/gate-enforcement-map.md` now describes the mechanisms that actually fire (the Tier-3 hook does not cover fetcher/link-policy, and said so; the map claimed it did).
6. **Retro log.** `docs/AGENT-RETROS.md` carries four rows drawn only from this repo's change records: PAR-704/706 (a control that reported healthy while returning nothing), PAR-659 (three gates FAILed the budget breach, then cleared it on ratio-based re-checks and missed the residue), PAR-658 (a README example presented invented output as a real capture), PAR-656 (a security FAIL on defects a 473-test suite was blind to).
7. **Metrics.** `scripts/metrics.mjs` prints npm downloads and open issues for a human to paste. Deliberately not wired to Linear or to a schedule — that would be new automation in the issue that exists to reduce it. Dev-only; not shipped.
8. **Deprecation removals now have a mechanism.** A test fails when the version reaches the stated removal version while a deprecation branch still exists — covering `DOCS_CACHE_DIR`, the legacy config filename, and the `docs-cache-mcp` bin alias.
